# 国际化支持

微应用模板内置了轻量级国际化（i18n）方案，支持多语言翻译、占位符替换、配置引用等。

需要满足条件：
- Sun-Panel 主版本升级到 `v2.0.0-dev-14+`
- 微应用模板升级到 `v1.1.0+` 
- `app.config.js` 下配置参数 `{appJsonVersion: '1.1'}`，1.1及以上

## 目录结构

```
your-app/
├── locales/                    # 国际化语言文件（唯一翻译源）
│   ├── zh-CN.js               # 中文语言包
│   └── en-US.js               # 英文语言包
├── config/
│   └── app.config.js          # 应用配置（声明语言文件列表）
└── ...
```

## 快速开始

### 1. 配置应用信息

在 `config/app.config.js` 中，使用 `$t:KEY` 引用翻译键，并在 `locales` 数组中声明语言文件：

```js
export default {
  // 配置文件格式版本
  // 1.1: appInfo 使用 $t: 引用，翻译文件在 locales/ 目录
  appJsonVersion: '1.1',

  // 应用信息（使用 $t: 变量引用翻译）
  appInfo: {
    appName: '$t:APP_NAME',
    description: '$t:APP_DESCRIPTION',
    networkDescription: '$t:NETWORK_DESCRIPTION',
  },

  // 语言文件列表
  locales: [
    'locales/zh-CN.json',
    'locales/en-US.json',
  ],

  // ...其他配置
};
```

::: tip 提示
`config/*` 中的值使用 `$t:翻译键名` 格式引用。构建时，系统会自动解析这些引用并替换为对应语言的翻译文本。
:::

### 2. 创建语言包文件

在 `locales/` 目录下创建对应的语言包文件。文件名必须与 `locales` 数组中的文件名一致（去掉 `.json` 后缀，使用 `.js` 源文件）：

```js
// locales/zh-CN.js
export default {
  APP_NAME: '你好世界',
  APP_DESCRIPTION: 'Sun-Panel 演示微应用',
  NETWORK_DESCRIPTION: '无需链接任何三方网站',
  WIDGET_HELLO_NAME: '你好世界小部件',
  WIDGET_HELLO_DESCRIPTION: '这是一个演示小部件',
  GREETING: '你好, $1$!',
  // ...更多翻译
};
```

```js
// locales/en-US.js
export default {
  APP_NAME: 'Hello World',
  APP_DESCRIPTION: 'Sun-Panel Demo Micro App',
  NETWORK_DESCRIPTION: 'For demonstration purposes',
  WIDGET_HELLO_NAME: 'Hello World Widget',
  WIDGET_HELLO_DESCRIPTION: 'A demo widget',
  GREETING: 'Hello, $1$!',
  // ...更多翻译
};
```

### 3. 在组件中使用

在组件的配置文件中，调用 `initI18n` 初始化后即可使用 `t()` 函数：

```js
import { t, initI18n } from '../builtins/i18n/index.js';

// 在组件初始化时调用（通常在 onInitialized 中）
async onInitialized({ widgetInfo }) {
  const locale = this.spCtx?.language || 'zh-CN';
  const staticPath = this.spCtx?.staticPath || '';
  await initI18n(locale, staticPath);
}

// 使用 t() 函数获取翻译
const config = {
  name: t('WIDGET_HELLO_NAME'),
  description: t('WIDGET_HELLO_DESCRIPTION'),
};
```

## 在微应用的组件中使用

### `initI18n(locale, staticPath)` - 初始化国际化

初始化 i18n 实例，加载指定语言的翻译文件。应在组件初始化时调用。

**参数：**
- `locale` (string) - 当前语言标识符，如 `'zh-CN'`，通常从 `this.spCtx.language` 获取
- `staticPath` (string) - 静态资源路径，通常从 `this.spCtx.staticPath` 获取

**使用示例：**

```js
import { initI18n } from '../builtins/i18n/index.js';

async onInitialized({ widgetInfo }) {
  const locale = this.spCtx?.language || 'zh-CN';
  const staticPath = this.spCtx?.staticPath || '';
  await initI18n(locale, staticPath);
}
```

::: info 加载机制
- **开发模式**：通过 `import()` 从 `locales/*.js` 源文件直接加载
- **生产模式**：通过 `fetch` 从 `{staticPath}/locales/*.json` 加载编译后的 JSON 文件
:::

### `t(key, ...args)` - 翻译函数

根据当前语言环境翻译指定的键，支持占位符替换。

**参数：**
- `key` (string) - 翻译键名
- `...args` (any[]) - 可选的占位符替换参数

**返回值：** 翻译后的字符串（未找到时返回键名本身）

**示例：**

```js
import { t } from '../builtins/i18n/index.js';

// 基本翻译
t('APP_NAME');        // => '你好世界'
t('SETTINGS');        // => '设置'

// 带占位符的翻译
t('GREETING', '张三');  // => '你好, 张三!'
```

### `resolveConfig(config)` - 解析配置中的 $t: 引用

递归解析配置对象中所有 `$t:KEY` 格式的引用，替换为对应翻译。用于解析 `appInfo` 等配置。

**参数：**
- `config` (any) - 包含 `$t:KEY` 引用的配置对象

**返回值：** 解析后的配置对象

**示例：**

```js
import { resolveConfig } from '../builtins/i18n/index.js';

// 将 { appName: '$t:APP_NAME' } 解析为 { appName: '你好世界' }
const resolved = resolveConfig(appInfo);
```

### `setLocale(locale)` - 切换语言

动态切换当前语言环境，并重新初始化解析器。

**参数：**
- `locale` (string) - 目标语言标识符，如 `'en-US'`

**示例：**

```js
import { setLocale } from '../builtins/i18n/index.js';

await setLocale('en-US');
```

### `getLocale()` - 获取当前语言

返回当前语言环境的标识符字符串。

**返回值：** `string` - 当前语言标识符

## 占位符

占位符使用 `$1$`、`$2$`、`$3$` 格式，数字代表第几个参数（从 1 开始）：

```js
// locales/zh-CN.js
export default {
  GREETING: '你好, $1$!',
  WELCOME_USER_ROLE: '欢迎 $1$，您是 $2$',
};

// locales/en-US.js
export default {
  GREETING: 'Hello, $1$!',
  WELCOME_USER_ROLE: 'Welcome $1$, you are $2$',
};
```

```js
t('GREETING', '张三');                     // => '你好, 张三!'
t('WELCOME_USER_ROLE', '李四', '管理员');   // => '欢迎 李四，您是 管理员'
```

如果占位符对应的参数缺失，占位符将原样保留（如 `$1$`）。

## 语言回退机制

当翻译键在当前语言中未找到时，系统会按以下顺序回退查找：

1. **完整语言代码** - 如 `zh-CN`
2. **语言代码** - 去掉地区后缀，如 `zh`
3. **默认语言** - `zh-CN`

```js
// 假设当前语言为 zh-TW，但只有 zh-CN 的翻译
// 查找顺序：zh-TW → zh → zh-CN
t('SETTINGS');  // 如果 zh-TW 和 zh 都没有，会从 zh-CN 获取
```

## 构建流程

### 开发模式

开发模式下，`locales/*.js` 源文件通过 Vite 动态 import 直接加载：

```
locales/zh-CN.js → import() 动态加载 → i18n 实例
```

### 生产构建

构建时，`locales-generator.js` 将 `locales/*.js` 编译为 JSON 格式，输出到 `dist/locales/` 目录：

```
locales/zh-CN.js → locales-generator.js → dist/locales/zh-CN.json
locales/en-US.js → locales-generator.js → dist/locales/en-US.json
```

生产模式下，i18n 通过 `fetch` 从 `{staticPath}/locales/*.json` 加载翻译文件。

## 最佳实践

### 1. 键名规范

翻译键使用 `大写蛇形命名法`（UPPER_SNAKE_CASE）：

```js
// 推荐
export default {
  APP_NAME: '应用名称',
  WIDGET_HELLO_NAME: '小部件名称',
  SETTINGS_TITLE: '设置标题',
  WIDGET_CONFIG_BUTTON_SAVE: '保存小部件',
};
```

### 2. 文件命名

语言包文件名必须与 `app.config.js` 中 `locales` 数组的文件名对应：

| 语言 | 源文件 | 构建产物 | locales 声明 |
|------|--------|----------|-------------|
| 简体中文 | `locales/zh-CN.js` | `dist/locales/zh-CN.json` | `'locales/zh-CN.json'` |
| 英语 | `locales/en-US.js` | `dist/locales/en-US.json` | `'locales/en-US.json'` |
| 繁体中文 | `locales/zh-TW.js` | `dist/locales/zh-TW.json` | `'locales/zh-TW.json'` |

### 3. 保持翻译同步

所有语言包文件应包含相同的键。新增翻译时，记得同步更新所有语言包文件。

### 4. 仅翻译文本

只翻译用户可见的文本内容，以下内容**不要**国际化：

- 配置键名（如 `showLogo`、`textOption`）
- CSS 类名
- API 路径
- 数据节点标识

## 注意事项

1. **翻译源位置**：所有翻译应统一放在 `locales/` 目录下，不要在 `src/` 目录下创建语言文件
2. **不要直接修改构建产物**：`dist/locales/` 是构建输出，修改会被覆盖
3. **语言标识符格式**：遵循 [IETF BCP 47](https://www.rfc-editor.org/info/bcp47) 标准（如 `zh-CN`、`en-US`）
4. **初始化时机**：`initI18n` 是异步的，需要在 `await` 后使用 `t()` 函数
5. **未初始化时的行为**：如果 i18n 未初始化，`t()` 会返回键名本身，不会报错
